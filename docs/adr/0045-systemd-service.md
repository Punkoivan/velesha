# ADR-0045: Сервер Велеші як systemd user-unit

## Контекст
Досі сервер піднімався вручну (`nohup … & disown`) щоразу після зміни коду чи
перезавантаження машини. Причина термінова: WireGuard на цьому ноутбуці відмовив
(«Дія не підтримується») через оновлення пакету `linux` без перезавантаження —
модулі ядра для запущеного `7.2.3-arch1-3` вже видалено, є лише для
встановленого `7.2.6-arch2-1`; після ребута має запрацювати. Перед
перезавантаженням варто мати надійний спосіб піднімати сервер автоматично.

## Рішення
- `api/run-server.sh` — обгортка: `cd api`, потрібні змінні середовища
  (`CHAT_PROVIDER=openai`, `CHAT_MODEL=gpt-5.6-luna`, `CHAT_REASONING=none`,
  `LOG_CALLER_PROMPT=1`), той самий ланцюжок `sops exec-env` що й раніше, але
  `exec uv run uvicorn …` на передньому плані (без `nohup`/`&`/`disown` —
  процесом володіє systemd, він же забирає stdout/stderr у journal).
- `~/.config/systemd/user/velesha.service` (user-unit, не системний — ключ age
  лежить у `$HOME`, тож user-контекст природніший): `Restart=on-failure`,
  `WantedBy=default.target`.
- `loginctl enable-linger punka` — інакше user-юніти стартують лише після
  інтерактивного входу, а тут потрібен автозапуск при завантаженні машини.
- **Новий шлях перезапуску:** `systemctl --user restart velesha.service`,
  журнал — `journalctl --user -u velesha.service -f`. Ручний `nohup`-запуск
  більше не потрібен.

## Побічна знахідка
Журнал systemd одразу показав `WARNING: Duplicate tool name 'get_watched_movies'`
на кожному запиті — `tools_for()` додавав його схему вдруге (він і так
безумовно в базовому `TOOLS`, бо не входить у `CONTROL_TOOLS`; зайвий рядок
з ADR-0042 дублював). Виправлено, і на додачу `tools_for` тепер дедублює
фінальний список за іменем інструмента — щоб такий клас помилки (інструмент
одночасно в базовому списку й у власному воротах) сам собою гасився, а не
чекав, поки хтось прочитає журнал.

## Наслідки
- Перезавантаження ноутбука більше не «губить» сервер — він підніметься сам.
- `run-server.sh` хардкодить робочу модель; зміна моделі — редагування файлу,
  не змінної оточення виклику.
- `DAILY_TOKEN_BUDGET` більше не підіймається вручну для тестів — сервіс завжди
  стартує зі стандартним лімітом (ADR-0025).
