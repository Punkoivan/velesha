# ADR-0062: Корм для собаки — автоматичне списання з Grocy і попередження «закінчується»

- **Status**: accepted
- **Date**: 2026-10-03

## Контекст

Користувач хоче знати залишок корму для Еббі і отримати сповіщення,
коли треба купувати новий. Еббі їсть фіксовано: 2×75 г (ранок, вечір).
Дата відкриття пачки неважлива — облік за вагою.

## Рішення

- Grocy — єдине джерело правди: товар «Корм для собаки Nature's
  Protection Adult Lamb» (id 169, грами, «Кладова»), нова група
  «Собака» (там же будуть таблетки від кліщів тощо; порожню «Тварини»
  видалено). `min_stock_amount` = 1050 г (7 днів) — щоб і в UI Grocy
  було видно.
- `api/pet_feed.py` — фоновий цикл (раз на хвилину, поруч із
  `reminder_poll_loop`): кожен слот із `PET_FEED_SCHEDULE`
  (`"08:00=75,20:00=75"`) списує свої грами. Прогрес — `last_fed` у
  `data/pet_feed.json`; пропущені через простій слоти доганяються (не
  більше 3 днів), перший запуск стартує з «зараз» без бекфілу.
  Зберігається після кожного слоту — збій посеред доганяння не спише
  двічі.
- Коли запас ≤ денна норма × `PET_FEED_WARN_DAYS` (7): одне
  повідомлення в Telegram і корм у список покупок Grocy
  (`PET_FEED_PACK_G` = 18000). `warned` скидається, щойно запас знову
  вище порогу — тобто після «купили корм» через `grocy_add_stock`.
- У системному промпті — факт про Еббі і заборона списувати корм вручну
  за годування (інакше «погодували Еббі» списало б двічі).

## Наслідки

- Фактичні порції «приблизно 75 г» — залишок у Grocy дрейфуватиме.
  Коригування: інвентаризація в Grocy або «в пачці лишилось N кг»
  (поки що вручну в Grocy; окремого інструменту немає).
- Зміна раціону/часу — лише `run-server.sh` і рестарт.
- Сервер вимкнений > 3 днів — частина годувань не спишеться
  (запас завищиться). Свідомо: краще недосписати, ніж списати купу
  за раз через збій годинника.
