# ADR-0046: Semantic search over personal notes; notes_search always offered

- **Status**: accepted
- **Date**: 2026-09-23

## Context

Голосовий сценарій: сказати «поклав батарейки в шухляду в столі», пізніше
спитати «а де батарейки» і отримати відповідь з нотатки. Виявились дві
окремі проблеми:

1. `notes_search` пропонувався моделі лише коли повідомлення саме містило
   слово «нотатк» чи «що я казав/записував» (`_NOTE_READ_RE`) — природне
   «де X» цього не зачіпало, і тулза моделі просто не діставалась.
2. Пошук був підрядковим за першими 5 символами слова (`w[:5] in text`) —
   працює для точного слова, але не для перефразувань («акумулятори» замість
   «батарейки»).

## Рішення

- `notes_search` (лише читання, дешевий: читає невеликий персональний
  JSONL-файл) тепер **завжди пропонується**, тим самим патерном, що
  ADR-0029 застосував до `toloka_search`, і цю сесію — до `get_reminders`.
  `note_add` (змінює стан) лишається за явним тригер-словом
  (`запиши`/`запам'ятай`/`занотуй`/...) — без цього кожна репліка ризикує
  стати нотаткою.
- При записі нотатки (`tool_note_add`) текст ще й ембедиться (`bge-m3`,
  той самий `search_backend.embed`, що й для рецептів/історії) і вектор
  зберігається просто в рядку JSONL (округлено до 5 знаків, щоб не
  роздувати файл).
- При пошуку (`tool_notes_search`) підрядковий збіг лишається (швидкий,
  точний для дослівного слова) і доповнюється семантичним — косинусна
  схожість, порахована локально в Python (без Qdrant: особистих нотаток
  мало, окремий колекшн і мультитенантна фільтрація — зайва інфраструктура
  для цього обсягу). Поріг схожості `_NOTES_SIM_THRESHOLD = 0.5`, підібраний
  емпірично на кількох перефразуваннях.
- Якщо embed-сервер недоступний під час запису чи пошуку — тихо
  деградуємо до самого підрядкового пошуку (нотатка все одно зберігається,
  просто без вектора).

## Альтернативи

- **Qdrant-колекція для нотаток** — той самий підхід, що інші джерела
  (ADR-0002/0003), але для персональних нотаток на людину додає складність
  (окрема колекція чи фільтр по користувачу — і ризик витоку між
  користувачами при помилці фільтра) без реальної переваги: обсяг даних
  на людину — десятки-сотні рядків, а не тисячі документів.
- **Іменовані нотатки** («Де речі?» як окремий документ) — розглядалось,
  відхилено: користувачу досить однієї спільної стрічки нотаток на
  людину з семантичним пошуком за темою, без потреби відкривати конкретну
  нотатку на ім'я.

## Наслідки

- Формат `data/notes/<user>.jsonl` тепер має необов'язкове поле `vec`;
  старі рядки без нього просто не беруть участі в семантичному ранжуванні
  (підрядковий пошук і показ «останніх» працюють як раніше).
- Файл нотаток трохи важчий (вектор ~1024 округлених float на рядок,
  ×5 символів ≈ кілька КБ на нотатку) — незначно для особистого обсягу.
