# ADR-0072: Адмін-права для окремого спільного пристрою; коротка відмова замість блукання

- **Status**: accepted
- **Date**: 2026-10-05

## Контекст

З s21 (спільний пристрій, ADR-0069) запит «скільки ми роздали торенті
серіалу Декстер» лишився без відповіді: інструменти qBittorrent/Толоки
адмінські (ADR-0035), спільний пристрій їх не бачив, а модель, замість
сказати це, перебирала інші інструменти (Jellyfin, стан HA) до ліміту в
6 викликів моделі.

Користувач хоче з s21 повний доступ до торентів (і запис), пам'ять при
цьому лишається спільною.

## Рішення

- `VELESHA_ADMIN_DEVICES` (зараз `s21-voice`): пристрій з мітки
  `Velesha-User:` (`users.set_device`) робить `is_admin()` істинним,
  незалежно від того, що особа — `shared`. Інші спільні пристрої (планшет)
  — без адмін-прав, доки їх не додано.
- У системному промпті — правило: немає потрібного інструмента → одразу
  одне речення про це, без обхідних шляхів; для не-адміна — прямо названо,
  що торенти з цього пристрою недоступні.
