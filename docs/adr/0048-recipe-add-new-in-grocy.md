# ADR-0048: recipe_add — новий рецепт з нуля напряму в Grocy, без Tandoor

- **Status**: accepted
- **Date**: 2026-09-24

## Контекст

«Хотів додати рецепт комбучі» впирався в те, що `grocy_recipe_import`
переносить лише рецепт, який **вже є в Tandoor** — для нового рецепта
(власного чи знайденого в інтернеті) переносити нема звідки. Окремий шлях
через Tandoor (створити там, заіндексувати в Qdrant, потім імпортувати)
відкинуто одразу — Tandoor тут планують прибрати, тож нового коду на
Tandoor заводити не варто.

## Рішення

`recipe_add(title, ingredients: list[str], steps: list[str], confirm)` —
пише рецепт напряму в Grocy, обходячи Tandoor повністю. Переговорює вже
наявну машинерію `grocy_recipe_import`:
- Інгредієнти (довільний текст із кількостями, напр. «200 г цукру»)
  проганяються через той самий `_build_draft`/`_extract_ingredients`
  (LLM-парсинг у структуру, зіставлення з продуктами Grocy).
- Той самий draft/confirm цикл і той самий `_write_draft`, з іншим
  текстом опису рецепта (не «з Tandoor», а «створено голосом»).
- Стан чернетки — той самий `_rs()`, що й у `grocy_recipe_import`:
  одна активна чернетка рецепта на користувача, як і раніше.
- Гейт: той самий розширений `_GROCY_IMPORT_RE` (ADR — правка гейту
  сесії 2026-09-24), що вже ловить природні «додай/перенеси рецепт X».
  Обидва інструменти пропонуються разом — модель сама вирішує: якщо
  `grocy_recipe_import` каже «немає в Tandoor», викликає `recipe_add`.

## Наслідки

- Кроки приготування («steps») зараз лише зберігаються текстом в описі
  Grocy-рецепта — Grocy не має окремого поля під покрокову інструкцію
  так, як Tandoor; для «покрокового проведення по рецепту» голосом
  знадобиться окрема робота пізніше.
- Коли Tandoor піде, `grocy_recipe_import` втратить сенс і його можна
  буде прибрати — `recipe_add` від цього не залежить.
