# ADR-0065: `recipe_add` — повні інгредієнти, вибір товару моделлю з каталогу

- **Status**: accepted
- **Date**: 2026-10-03

## Контекст

Розбір рецептів (ADR-0064) показав, чому панелі інгредієнтів були
неповні й хибні — і `recipe_add` досі так працював:

- рядок без кількості («сіль за смаком») — відкидався;
- одиниця не сходилась з одиницею товару («2 ст.л.» меду, товар у л;
  спеції в пачках) — відкидався;
- вода — свідомо виключалась;
- нечітке зіставлення назв: `_grocy_match(strict=True)` вважало збігом,
  коли слово запиту — префікс слова товару («картопля» → «Крохмаль
  картопляний»);
- опис — текст «1. …».

## Рішення

- `_extract_ingredients` отримує каталог товарів Grocy і повертає для
  кожного інгредієнта точну назву товару з каталогу (або `new_name`),
  кількість і одиницю (включно з ч.л./ст.л./склянка), текст кількості як
  у рецепті, примітку, `optional`, групу. Код приймає лише точну назву з
  каталогу — жодного нечіткого зіставлення.
- `_build_draft` нічого не відкидає: ложки/склянки → мл (для товарів на
  вагу 1 мл ≈ 1 г); що не переводиться або без кількості — режим «лише
  наявність»; «за бажанням / для подачі / вода для пари» — режим
  «необов'язково» (ті самі три режими, що в ADR-0064).
- `_write_draft` пише `variable_amount`, примітку, групу і прапорці
  режиму; новий товар створюється для будь-якого режиму.
- `recipe_add` пише кроки як HTML `<ol>`.

## Наслідки

- Один виклик моделі довший (каталог ~170 назв, ~1,5 тис. токенів).
- Модель може помилитись із вибором товару — чернетка показує
  «новий товар» / «лише наявність» / «за бажанням», користувач бачить це
  до запису.
