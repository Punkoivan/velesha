# ADR-0056: Telegram-сповіщення про початок прибирання

- **Status**: accepted
- **Date**: 2026-09-27

## Контекст

Прибирання може запускатись без людини поруч (за розкладом
`vacuum_schedule`) — хочеться знати, що воно реально почалось, з якою
кімнатою й режимом.

## Рішення

`_notify_vacuum_start(area_id, mode, user)` викликається зі
`_do_vacuum_action` при успішному `action == "start"` — і для прямого
`vacuum_control`, і для запланованого запуску через поллер (ADR-0049/
0051), оскільки обидва йдуть через ту саму функцію. Шле через
`telegram_client` (ADR-0054) на `TELEGRAM_CHAT_ID_<USER>`; текст —
назва кімнати (реверс-резолв area_id → людська назва через
`_areas()`) і режим, якщо заданий. Best-effort — помилка надсилання
лише логується, не ламає саму дію пилососа.

`user` передається явним параметром, а не через `users.current()`:
у поллері `users.current()` відображає останній реальний HTTP-запит,
а не той календар/користувача, чия запланована дія зараз обробляється
(та сама причина, що вже врахована для `_reminder_notify_target`/
`_telegram_chat_id` в ADR-0049).

## Наслідки

- `_resolve_area`/`_area_name` тепер діляться однією функцією
  оновлення кешу (`_areas()`) — раніше логіка кешування дублювалась.
