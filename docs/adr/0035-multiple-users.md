# ADR-0035: Кілька користувачів

## Контекст
Асистентом користуються двоє. HA не передає особу для OpenAI-сумісних агентів
(`llama_cpp` шле лише `user=<conversation_id>`, без `user_id`/`device_id`).
Рішення користувача: Jellyfin, Grocy, запаси, рецепти, історія дому — спільні;
обмеження лише для адміністрування; нотатки — окремі.

## Рішення
- Особа = API-ключ. Для кожної людини в HA свій запис `llama_cpp` з тією ж
  адресою, але своїм ключем; вибирається в її Assist. `api/users.py`:
  `VELESHA_USERS="ключ:ім'я,…"`, `VELESHA_ADMINS="ім'я"` (за замовчуванням
  перший). Невідомий ключ → 401. Без `VELESHA_USERS` — режим одного
  користувача без автентифікації, викликач — адмін (як було).
- Адміністративні інструменти лише адміну (`ADMIN_TOOLS`: qBittorrent і Толока):
  не пропонуються моделі й додатково відхиляються в `call_tool`.
- Окремо для кожного користувача: коротка пам'ять розмови (ADR-0034), стан
  імпорту рецептів, особисті нотатки `api/data/notes/<ім'я>.jsonl` (gitignored).
  Інструменти `note_add` (лише за фразою «запиши/запам'ятай…») і `notes_search`
  завжди працюють над файлом поточного користувача, іншого не вказати.
- Файли існуючих нотаток Obsidian не чіпаються.

## Наслідки
- Стан торрент-пошуку лишається глобальним: ним користується лише адмін.
- Ключі — секрети (`api/secrets.enc.env`), зашифровує користувач.
- Нотатки, зроблені до увімкнення користувачів, лежать у `default.jsonl`; після
  увімкнення їх треба перейменувати на файл адміна.
- Стан у RAM, після перезапуску пам'ять розмов порожня.
- Схема тримається на тому, що ключ не витікає; голосового розпізнавання немає.
  Якщо HA колись передасть `user_id`, ключі можна замінити на нього.
