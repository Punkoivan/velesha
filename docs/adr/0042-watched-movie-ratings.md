# ADR-0042: Особисті оцінки переглянутих фільмів (SQLite + Qdrant)

## Контекст
Чернетку принесено ззовні (`velesha-movie-tracker-todo.md`); мета — власні оцінки й
відгуки на переглянуте (Jellyfin рейтингів не тримає в тексті), і семантичні поради
на їх основі. Чернетка не знала поточного стану проєкту.

## Розбіжності з чернеткою й чому
- **«Додати tool у наш MCP-сервер Jellyfin»** — такого сервера нема: Jellyfin тепер
  через сторонній `jellyfin-mcp` (ADR-0038), який ми лише патчимо. Інструменти —
  звичайні функції в `tools.py`, як усе інше.
- **«SQLite на HA-сервері з бекапом»** — агент живе на цій машині, не на HA-сервері;
  `api/data/movies.db` поруч з рештою власного стану (`usage.json`, нотатки).
  Бекап цієї машини — ширше питання, не вирішене тут.
- **«Визначитись, яка embedding-модель»** — вже вирішено (`search_backend.embed`,
  bge-m3, спільний Qdrant-клієнт); нова колекція `watched_movies` додана в
  `COLLECTIONS`, тож `search_knowledge` одразу її бачить.
- **Тригер індексації** — варіант A (одразу після запису), як в чернетці: обсяг
  малий, і це узгоджується зі стилем решти інструментів (синхронно, без черги).

## Ключ запису — не `jellyfin_id`
Користувач видаляє файли з Jellyfin, коли закінчується місце, тож локальний id
недовговічний. Ключ: `imdb_id` (стійкий, не залежить від Jellyfin), інакше
`(title, year)` без урахування регістру. `title` — оригінальна назва (англійська/
мовою виробництва), не український дубляж, щоб зіставлення не залежало від
локалізації Jellyfin; за потреби модель бере `imdb_id` з `provider_ids.Imdb` через
`jellyfin_get_item`. `director` — необов'язково, для додаткової однозначності.

## Рішення
- `api/movies_db.py`: SQLite, `log_watched_movie` — upsert за `imdb_id` або
  `title+year`, скидає `qdrant_indexed=0` при повторній оцінці.
- `tools.py`: `log_watched_movie` (лише за прямою фразою оцінити/записати) і
  `get_watched_movies` (завжди, фільтр за жанром/мін. оцінкою). Оцінка 0–10.
- Індексація одразу після запису в колекцію `watched_movies` (bge-m3, cosine;
  створюється лінькво при першому записі); текст: назва, рік, режисер, жанри,
  оцінка, відгук. Помилка індексації не блокує запис — SQLite є джерелом істини,
  `qdrant_indexed=0` дозволяє доіндексувати пізніше (доіндексація batch-ом ще не
  написана — відкрите питання).
- `search_knowledge(source="watched_movies")` — семантичні поради на основі оцінок.

## Перевірено
Запис, повторна оцінка того самого фільму (за title+year без imdb_id, і за
imdb_id) оновлює один рядок, а не дублює; відхилення без року/з оцінкою поза
0–10; наскрізно через агента (gpt-5.6-luna): «оціни Байкери на 9…» →
`log_watched_movie`, «які фільми я найвище оцінив?» → `get_watched_movies`.

## Відкрите
- Бекап `api/data/`.
- Пакетна доіндексація `qdrant_indexed=0` (зараз лише одразу після запису).
- Формат жанрів — з Jellyfin, довільний ввід не підтримується.
