# ADR-0080: Безпечна робота з посиланнями користувачів (SSRF, торенти)

- **Status**: accepted
- **Date**: 2026-10-07

## Контекст

`film_find` (ADR-0079) для «будь-якого сайту» сам завантажував сторінку за
посиланням з повідомлення, а `qbittorrent_add` віддавав qBittorrent будь-яке
`http(s)`. Посилання на `http://192.168.88.80:8123/…` чи
`http://localhost:8083` змусило б сервер (чи HA-хост із qBittorrent)
звернутись до сусідів у локальній мережі від свого імені (SSRF).

## Рішення

- `api/safe_http.py`: `check(url)` — лише http/https, порт за
  замовчуванням, без логіна/пароля в URL, ім'я сайту резолвиться лише в
  публічні адреси (`ip.is_global`, не multicast; IPv4 і IPv6).
  `fetch_html` перевіряє кожен перехід (переадресації вручну, ≤ 3),
  ≤ 512 КБ, лише HTML, таймаути 5/10 с. З сторінки виходить лише заголовок
  (≤ 200 символів, без керуючих символів) — не текст сторінки.
- Вікіпедія / IMDb / TMDB, як і раніше, — через їхні API за id з посилання,
  сторінка не завантажується.
- `qbittorrent_add`: лише `magnet:` або `https://toloka.to` (і піддомени).
- Залишковий ризик: DNS rebinding (ім'я, що резолвиться в публічну адресу
  для перевірки й у приватну — для запиту) — потребує підконтрольного
  зловмисникові DNS і посилання від користувача з білого списку; прийнято.
